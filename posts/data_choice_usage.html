Data.Choice

Этот модуль создан для решения проблемы "булевой слепоты" (boolean blindness). Когда функция принимает значения типа Bool, в коде вызова (например, foo True False) абсолютно неясно, за что отвечают эти флаги. Тип Data.Choice заменяет их на именованные логические типы (labeled booleans), а находится он в пакете choice

Необходимые расширения

Для базовой работы понадобятся следующие языковые расширения:

{-# LANGUAGE DataKinds #-}
{-# LANGUAGE OverloadedLabels #-}
{-# LANGUAGE PatternSynonyms #-}

Пример использования

Вместо Bool в типе функции указывается Choice "имя_флага" (где "имя_флага" обозначает назначение замещённого булевого аргумента - для чего он используется), а для значений используются разные конструкторы, вроде Is (который соответствует значению True) и Isn't (для False) вместе с меткой #имя_флага (имя внутри метки должно соответствовать имени, указанному в типе Choice). Есть и другие конструкторы, но их мы рассмотрим позже. Пример:

logMessage :: String -> Choice "verbose" -> IO ()
logMessage msg (Is #verbose) = putStrLn $ "[LOG][DEBUG]: " ++ msg
logMessage msg (Isn't #verbose) = putStrLn msg

Здесь #verbose - это перегруженная метка типа (overloaded label), которая "связывает" переданное значение с именем флага.

При вызове функции сразу становится очевидно, какой флаг передаётся (в данном случае - verbose) и в каком состоянии (Is для состояния True и Isn't для False):

main :: IO ()
main = do
  logMessage "Система запущена" (Is #verbose)
  logMessage "Просто текст" (Isn't #verbose)

Если попытаться передать туда флаг с другим именем (например, Is #debug), компилятор выдаст ошибку на этапе компиляции, защищая вас от ошибок.

Устройство Choice

Так написано в исходниках:

data Choice (a :: Symbol)
  = Off {-# UNPACK #-} !(Label a)
  | On {-# UNPACK #-} !(Label a)
  deriving (Eq, Ord, Generic, Typeable)

Как видно, здесь всего пара конструкторов Off и On, которые соответствуют значениям False и True соответственно. Сам тип Choice параметризован переменной типа с кайндом Symbol, т.е. строкой на уровне типов, которая определяет тип Label.

Здесь используется прагма {-# UNPACK #-} для указания компилятору GHC оптимизировать память, убрав лишние ссылки (указатели) и встроив данные напрямую. То есть прагма позволяет хранить содержимое поля непосредственно в конструкторе, без отдельного указателя на heap.

Замечание. Для использования прагмы должны быть соблюдены два условия:
  • Поле должно быть строгим (strict) - перед типом обязательно должен стоять восклицательный знак (!). Это гарантирует, что данные не ленивые и вычисляются сразу.
  • Тип должен иметь чёткие границы - компилятор должен точно знать размер распаковываемых данных во время сборки.
Это мы и видим в объявлении выше.

Что такое Label

По сути Label - это аналог Proxy, но несёт информацию на уровне типа исключительно в виде строки (кайнд Symbol). Оба типа - фантомные. У них нет полезных данных в рантайме, они существуют только чтобы "протащить" тип. Определение Label:

data Label (a :: Symbol) = Label deriving (Eq, Ord, Show)

Как видно, конструктор здесь один.

Как создавать значения

Паттерны ниже символизируют True:

pattern Do      :: Label a -> Choice a
pattern Is      :: Label a -> Choice a
pattern With    :: Label a -> Choice a
pattern Must    :: Label a -> Choice a
pattern Can     :: Label a -> Choice a
pattern Should  :: Label a -> Choice a

Имена у них разные для самых разных случаев, но все они реализованы одинаково - через конструктор On, например: 

pattern Do x = On x
-- pattern With x = On x
-- ...

Паттерны ниже символизируют False:

pattern Don't     :: Label a -> Choice a
pattern Isn't     :: Label a -> Choice a
pattern Without   :: Label a -> Choice a
pattern Mustn't   :: Label a -> Choice a
pattern Can't     :: Label a -> Choice a
pattern Shouldn't :: Label a -> Choice a

Они тоже реализованы одинаково - через конструктор Off, например: 

pattern Don't x = Off x
-- pattern Without x = Off x
-- ...

Т.е. в один из этих паттернов передаётся метка (конструктор у неё только один - Label, и сам тип параметризован строкой), а она передаётся конструктору Choice, который будет параметризован строкой из метки.

Как работает #label

Синтаксис #имя_метки (например, #block, #ssl, #admin) - это перегруженная метка. Она появилась в Haskell благодаря языковому расширению {-# LANGUAGE OverloadedLabels #-}. Когда компилятор встречает метку вроде #block, он автоматически раскрывает его в вызов специального метода fromLabel: 

-- Пишем:
#block

-- GHC превращает это в:
fromLabel @"block"

Символ @ означает применение типа "напрямую" (type applications). То есть строка "block" "уходит внутрь" системы типов как Symbol - она становится значением для переменной типа в классе типов (увидим это ниже).

Класс IsLabel

Что это за fromLabel? Он из модуля GHC.OverloadedLabels, где определён такой класс: 

-- неявно:
-- class forall x a. IsLabel (x :: Symbol) a where ...

class IsLabel (x :: Symbol) a where
  fromLabel :: a

У метода нет аргументов, а какой именно экземпляр вызвать, определяется парой (x, a) - обе переменные должны выводиться из вызова. При вызове мы можем передать значение для скрытого параметра x через @something. Можно было бы и для a - но это избыточно в данном случае, т.е. его тип очевиден из места вызова.

То есть при вызове метода мы передаём аргументы (их типы известны) и типы через @ (если в этом есть необходимость), и по всему этому набору определяется, метод какого именно инстанса выбрать.

Неявный forall перечисляет параметры класса строго по порядку слева направо: сначала x, потом a. Поэтому, когда мы пишем fromLabel @"block", тип "block" передаётся в первую переменную в forall, то есть в x. Если бы мы захотели передать ещё и тип результата a руками, можно было бы использовать второй @: fromLabel @"block" @(Label "block").

Реализация инстанса

Метод fromLabel вызывается в паттернах, которые требуют в качестве первого аргумента значение типа Label x, а это значит, что модуль должен реализовать этот класс для данного типа, и он это делает так: 

-- неявно:
-- instance forall x x'. x ~ x' => IsLabel x (Label x') where

instance x ~ x' => IsLabel x (Label x') where
  fromLabel = Label

В Haskell знак тильды ~ означает ограничение равенства типов (type equality constraint), и оно проверяется во время компиляции. Запись x ~ x' читается как: "Тип x должен быть абсолютно тем же самым типом, что и x'". Если компилятор обнаружит, что это разные типы, программа не скомпилируется. В целом, конструкция x ~ x' в контексте инстансов классов типов используется как для вывода типов (type inference), так и для их пассивной проверки.

Как будет работать вызов fromLabel @"something":

  1. Выражение @"something" фиксирует, что x = "something".
  2. Ожидаемый тип выражения определяет, что a имеет тип Label ? для некоторой переменной ?.
  3. GHC ищет инстанс, который сопоставляется с запросом IsLabel x (Label ?). Подходит instance x ~ x' => IsLabel x (Label x') - сопоставление даёт ? = x'
  4. В инстансе указано ограничение x ~ x', а это вместе с x = "something" даёт x' = "something". Таким образом, возвращаемое значение Label имеет тип Label "something".
  5. Когда значение типа Label "something" передаётся в паттерн Is (типа Label a -> Choice a), переменная a в Choice a становится равной "something", и всё выражение получает тип Choice "something".
  6. Компилятор проверяет, что Choice "something" совпадает с ожидаемым типом.

Утилитные функции

Есть ещё полезные утилитные функции. Они позволяют бесшовно переходить от безопасных именованных флагов к стандартным булевым значениям и обратно, а также работать с этими флагами как с булевыми значениями. 

fromBool :: forall   (a :: Symbol). Bool -> Choice a
toBool   :: forall   (a :: Symbol). Choice a -> Bool
isFalse  :: forall   (a :: Symbol). Choice a -> Bool
isTrue   :: forall   (a :: Symbol). Choice a -> Bool
choice   :: forall a (b :: Symbol). a -> a -> Choice b -> a

Функция fromBool превращает обычный Bool в безопасный именованный флаг (мы иногда должны указать имя метки через @имя_метки, так как из True или False компилятор иногда не может сам определить это имя), а toBool превращает флаг обратно в обычный Bool.

Пример. Представьте, что мы получаем статус из конфигурационного JSON-файла в виде обычного Bool, в своей логике хотим использовать безопасный Choice, а в сторонних библиотеках требуют опять Bool. Использование этих функций может выглядеть так: 

{-# LANGUAGE DataKinds #-}
{-# LANGUAGE OverloadedLabels #-}

import Data.Choice (Choice, fromBool, toBool)

main :: IO ()
main = do
    let configValue = True -- прилетело из конфига

    -- Превращаем обычный Bool в Choice "useSandbox"
    -- Переменная a не выводится из Bool, поэтому её нужно задать явно
    let secureFlag = fromBool @"useSandbox" configValue

    processPayment secureFlag

-- Функция, которая требует безопасный флаг
processPayment :: Choice "useSandbox" -> IO ()
processPayment flag = do
    -- Нам нужно вызвать стороннюю библиотеку, которая принимает только обычный Bool
    let rawBool = toBool flag
    print $ "Вызов стороннего API с параметром: " ++ show rawBool

Функции isTrue и isFalse позволяют быстро проверить состояние.

Эти функции возвращают обычный Bool и нужны для простых проверок (например, внутри стандартных if-then-else выражений), чтобы не приходилось каждый раз писать case-of с паттернами. Пример использования: 

import Data.Choice (Choice, pattern Do, isTrue, isFalse)

checkAccess :: Choice "isAdmin" -> IO ()
checkAccess flag = do
    -- Вместо громоздкого case-of пишем простое условие:
    if isTrue flag
        then putStrLn "Доступ разрешен в панель администратора."
        else putStrLn "Отказ в доступе."

Функция choice - функциональный аналог if-then-else - функционально делает ровно то же самое, что и стандартная функция bool из модуля Data.Bool, но bool работает с Bool, а choice - с Choice b. Она принимает три аргумента:

  1. Значение, если флаг Off (то есть False).
  2. Значение, если флаг On (то есть True).
  3. Сам флаг типа Choice a.
Важно помнить порядок аргументов: как и в стандартной функции bool, сначала идёт ветка для False, а затем для True. Насколько мне известно, это сделано для удобства каррирования. 
{-# LANGUAGE DataKinds #-}
{-# LANGUAGE OverloadedLabels #-}
{-# LANGUAGE PatternSynonyms #-}

import Data.Choice (Choice, pattern Do, pattern Don't, choice)

getLogMessage :: Choice "verbose" -> String
getLogMessage flag = choice "Краткий лог" "Очень подробный и длинный лог" flag

main :: IO ()
main = do
    putStrLn $ getLogMessage (Do #verbose)    -- Выведет: "Очень подробный и длинный лог"
    putStrLn $ getLogMessage (Don't #verbose) -- Выведет: "Краткий лог"
